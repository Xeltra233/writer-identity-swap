# 编写者身份替换 (Writer Identity Swap)

在**出站提示词**里把预设的「故事编写者」身份替换成你指定的名字。预设文件、聊天记录、世界书本身都不会被改写。

例：`小猫之神` 预设里模型自称「小猫之神」——你把它改成「赤狐」，发给 API 的所有消息里都变成赤狐，包括 `<details><summary>小猫之神的留言</summary>`、`——🎬小猫小剧场——`、`[💬|小猫之神的心声|…]` 这类片段，以及历史消息里同样的写法。

## 安装

1. 把整个 `writer-identity-swap` 目录放进任一位置（两处都实测可加载）：
   - 用户目录 `SillyTavern/data/<user>/extensions/writer-identity-swap/` —— 仅该用户可用；
   - 全局目录 `SillyTavern/public/scripts/extensions/third-party/writer-identity-swap/` —— 所有用户可见。
2. 刷新页面，右侧「扩展程序」面板里出现「编写者身份替换」。

同名两处都放时，ST 只加载**用户目录**那份（`/api/extensions/discover` 会把全局的同名项过滤掉，静态文件也先查用户目录）；升级时别只替换全局副本，否则改的是一份不会被加载的文件。

| 安装位置 | discover 返回 | 实测 |
| --- | --- | --- |
| 用户目录 | `{type: "local"}` | 面板 1 个；历史 e2e 全在此模式 |
| 全局目录 | `{type: "global"}` | 面板 1 个；30 条消息 / 原身份 0 / 目标 26 |
| 两处同时 | 仅 `{type: "local"}` | 面板 1 个，未重复挂钩 |

无 `manifest.hooks` 字段，扩展自己在 `index.js` 末尾 `void init()` 启动，兼容 1.13.x/1.16.x 这类没有 hooks 机制的老版本。

## 用法

1. 选中要用的预设（例：`小猫之神`）。
2. 面板会自动识别出「编写者身份」（预设名、结构化声明、对话转录里的 `|X|` 标签等都参与打分）。
3. 在「改成」里填新身份（例：`赤狐`）。「原身份」留空 = 用自动识别结果；手填 = 完全按你填的来（自动识别结果不再参与）。
   需要连简称一起替换时（例：剧场标题写的是 `——🎬小猫小剧场——` 而不是全名），在「额外别名」里填 `小猫`。
4. 直接聊天。替换发生在请求发出前的最后一刻。

面板选项：

| 选项 | 说明 |
| --- | --- |
| 自动识别 | 从当前预设里推断编写者身份 |
| 用别名 | 连同识别出的别名一起替换（如 `超级魔法小狗`、`Femris`/`Femiris`、括号别名 `特图（Tet）`） |
| 额外别名 | 逗号分隔手动补充（如 `小猫`），始终生效；长名优先匹配，`小猫之神` 不会被拆成 `赤狐之神` |
| 含历史 | 历史里用户和 AI 的消息也替换。关掉则只改「系统提示/预设正文」，历史保留原样 |
| 忽略大小写 | `Ako`/`ako`、`Kasumi`/`kasumi` 都算命中（ASCII 边界严格，`Ako` 不会命中 `Ako1`） |
| 提示 | 每次替换后弹一条 toast |
| 同步目标 | 目标名字变更时同步写进各预设的配置 |

配置按预设保存：每个预设各自记住「原身份 / 别名 / 目标」，切预设自动切换，互不干扰。

### 斜杠命令与宏

- `/writer-status` — 当前预设、源身份（自动/手动）、别名、目标、上次替换计数。
- `/writer-set target=赤狐 source=小猫之神`（别名 `/writer`）— 不改 UI 直接配置。
- `/writer-toggle` — 临时开/关替换。
- `{{writer}}` / `{{writerTarget}}` / `{{writerAliases}}` — 在任意提示词里引用当前编写者身份。

## 工作原理

```
当前预设 prompts + prompt_order(启用项) + 扩展提示词
        │
        ├─ src/identity.js  打分识别编写者身份 → 候选(名字/别名/置信度/证据)
        │
        └─ src/replace.js   单次正则、长名优先、不级联；就地改写载荷里的字符串
                │
   发出前钩子 ├─ CHAT_COMPLETION_PROMPT_READY   （chat 数组，OpenAI/Claude/Google 等 chat 源）
             ├─ GENERATE_AFTER_DATA             （generate_data.prompt，含 generateRaw 链路）
             └─ GENERATE_AFTER_COMBINE_PROMPTS  （合并后的最终 prompt 字符串）
```

要点：

- **只改出站对象**：钩子里拿到的是即将 POST 的 `chat` / `prompt` 对象，就地改字符串；不写回预设、不写回聊天文件。
- **一遍替换**：所有源写法合成一个 alternation 正则，替换用回调取值，`赤狐之神` 不会再被二次命中；同一请求重复处理有 `Symbol` 级幂等标记。
- **整份载荷遍历**：钩子里拿到的是最终要发的对象（`chat[]` 或 `prompt` 字符串），替换对它做全量字符串遍历，与内容来源无关 —— 系统提示、示例对话、历史消息、`<details>` 标题、状态栏、其它扩展注入的文本，只要出现该身份就替换。
- **重名保护**：源身份与 `userName`/`characterName` 相同时给出警告；目标里包含源名字时给出提示（配合单遍替换不会层层膨胀）。

## 覆盖到的预设形态

对 `C:\project\test\预设\预设` 下 19 个真实预设实测，识别分四类：

- **A 转录标签**：`|小猫之神|` / `|用户|` —— 高置信。
- **B 结构化声明**：`核心搭档：X`、`身份：X`、`你是X…作家`、`名字就叫X`、`由X执笔` —— 高/中置信。
- **C 无名编写者**：只写「你是优秀的作家」，没给名字 —— 识别为空，手填即可。
- **D 无编写者概念**：身份来自角色卡 —— 识别为空，手填即可。

自动识别结果（由真实预设回归测试固化）：小猫之神→小猫之神、魔法小狗→小金、Monster_Home→👾、创世回廊→特图、云中梦→小金、FemirisDS→Femiris、Izumi→泉此方、Ako→Ako、狐神→狐神抚、咩咩→咩咩、图灵→Turing；TGbreak/char/剑仙/嗷呜酱/昆仑/糖糖公司/Kemini_Dramatron/Ny-Gemini 无名字（手填兜底）。

## 不在示例文件夹里的预设

替换本身与预设无关：插件只认「原身份字符串 → 目标字符串」，任何预设、任何后端都能换。区别只在于**原身份从哪来**：

1. **自动识别**：预设用 A/B 形态点名了编写者（`|X|` 标签、`核心搭档：X`、`身份：X`、`由X执笔`、`X的留言`、反复自述「我是X」、预设名就是身份名且正文反复出现）。
2. **手动指定**：预设没有具名编写者（C/D 形态）。在面板「原身份」里填一个字符串并保存（会自动记到该预设名下，`autoMode=false`），之后照常替换。例：TGbreak 里 `你是优秀的作家` → 填 `优秀的作家`，出站就变成 `你是赤狐`。
3. **额外别名**：同一身份在正文里有简称/别称（`小猫`、`超级魔法小狗`），填进「额外别名」。

判断某个预设能不能自动识别：切换到这个预设，面板顶部会显示「自动识别 / 手动已保存 / 未识别」，候选区会列出所有命中项（含只有 1~2 次命中的低置信候选，点一下即可采用）。

实测（本机 66 个真实预设，含示例目录 19 个 + 外部库 47 个）：

| 范围 | 数量 | 自动识别 | 需手填 |
| --- | --- | --- | --- |
| 示例目录 `预设\预设` | 19 | 11 | 8 |
| 外部库 `OpenAI Settings` | 47 | 20 | 27 |

手填的 27 个不是「换不了」，而是预设正文里根本没有写出编写者名字（`Default` 只有 `Write {{char}}'s next reply…`、`TGbreak` 只有「你是优秀的作家」、`7.15`、`昆仑` 等属于此类）；填了原身份后替换照常生效，已用 TGbreak 实测：`你是优秀的作家` → `你是赤狐`，载荷里 `优秀的作家` 计数 0。

自动识别的门槛（避免把章节小标题当成人名）：

- 只出现在一条声明、且全篇只出现 1~2 次的候选不自动套用（`作家流派:`、`叙事者分析核心`、`- 结尾模块：`、`|小说家|` 这类实测误报）。
- 自动采用要求「写作身份句式」证据，或分数 ≥ 60；其余候选只在面板里列出，点一下即可用。
- 频次本身也算证据：`{{//作者：泉此方` 这种只声明一次、但正文里出现 7 次的，仍会自动选中。

## 不修改文件的证据

e2e（真实 ST 实例 + 本地 mock 后端）跑完后的核对：

- 预设 JSON 的 md5 在发送前后完全一致。
- 聊天文件 `WIS-Test - *.jsonl` 里仍是原始身份（`|👾|`、`👾的留言`、`💬|👾的心声`），而同一时刻出站载荷里 `👾` 计数为 0、`赤狐` 计数 29。

完整抓包与复现记录保留在开发仓库中，未随插件发布。

## 限制

- 覆盖的是有钩子的链路：`Generate()` 全流程（chat 类后端走 `CHAT_COMPLETION_PROMPT_READY`，文本补全类后端走共享的 `GENERATE_AFTER_COMBINE_PROMPTS`）以及 `generateRaw()`（`GENERATE_AFTER_DATA`）。自己拼请求直接 `fetch` 的第三方扩展不经过这两个事件，不在覆盖范围内。
- 身份不是名字而是纯语气（「用温柔的口吻写」）时无从替换 —— 这是「身份命名」本身缺失，不是替换范围问题。
- 忽略大小写对非 ASCII 名字无效（CJK 无大小写概念）。
- 4 字以内的 CJK 别名默认不自动启用（太容易误伤普通词汇），需要的话填进「额外别名」。

## 开发

```bash
npm test        # 35 项单测：识别 / 替换 / 19 个真实预设回归 / 计数
```

- `src/identity.js`、`src/replace.js` 是纯模块（不 import 酒馆代码），可在 Node 里直接测。
- `index.js` 只做酒馆胶水：设置读写、事件钩子、UI、命令、宏。
- 检测/替换逻辑是纯函数（`src/identity.js`、`src/replace.js`），不依赖酒馆运行时，可直接用 Node 单测覆盖。
